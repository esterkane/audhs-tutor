# Känguru Tutor — Supabase & PostgreSQL Socratic Support Tutor

An evidence-grounded, Socratic tutor that trains you to support-engineering mastery of
Supabase and PostgreSQL. Runs fully locally on a Supabase CLI stack, with the official
docs (`llms.txt` → `llms-full.txt` + `llms/*.txt`) as the primary RAG corpus, web search
only where freshness or community evidence is needed, and a text + Mermaid + voice UI.

It is designed to run two ways:

1. **Standalone** — `make up` starts local Supabase; `make dev` starts FastAPI + Vite.
2. **As a sub-module of the AuDHS Tutor** — `backend/tutor` is a FastAPI router and
   `frontend/src/tutor` is a React route; both mount into the existing app.

## Quickstart (macOS, Apple Silicon)

```bash
# prerequisites: Docker-compatible runtime (Docker Desktop / OrbStack), Node 22+, uv (Python 3.12 is fetched by uv)
# psql is NOT required: all DB scripts use psycopg.
cp .env.example .env
make reset                         # start stack, db reset (migrations + seed), lab DB, lab 01
make smoke                         # verify stack, schema, seed, search, lab roles, lab 01
make ingest                        # fills docs_chunk from llms.txt (ARGS="--dry-run" first)
make dev                           # FastAPI :8020 + Vite :5180 (API_PORT / WEB_PORT to change)
make dev-user ARGS=--print-token   # local dev learner + access token for curl against /tutor/*
make refresh-schedule              # weekly docs refresh via pg_cron + pg_net (backend must be running)
make tts                           # optional: local German server voice (Piper); set TUTOR_TTS=server in .env
```

`make help` lists every target. `supabase/seed.sql` is generated by `make seed` from
`docs/curriculum.yaml` and `labs/*/lab.yaml`; do not edit it by hand.

Then open the tutor, say "Hallo", and answer its single opening question.

## Non-negotiables (mirrored in CLAUDE.md)

- Factual accuracy and citations outrank persona and speed.
- Never claim to have run a command the learner ran. The tutor only executes SQL in the
  disposable **lab** database, never against the learner's real projects.
- No secrets in client code. `service_role` stays server-side.
- RLS is never disabled as a "fix"; only as a labelled diagnostic experiment in the lab.

### Enrolled documentation checks

The scheduled refresh also compares already indexed guides and CLI or self-hosting command sections in `scripts/enrolled_reference_urls.txt` with the current official source. To run it alongside the normal incremental seed refresh, use `python scripts/ingest_llms.py --check-enrolled` with the usual local database settings. Check scheduler availability with `python scripts/refresh_schedule.py status`.

For a read-only index check on a local schedule, run `python scripts/ingest_llms.py --enrolled-only` with the local database URL. A systemd user timer can run this weekly with `Persistent=true` to catch up after downtime. The same check also runs through the vendor refresh manager when pg_cron is configured.

Each check writes a receipt under `data/reference-review/<run>/review.json`. A changed entry includes the SHA-256 of the indexed snapshot and the new Markdown file in that directory. Invalid or unreachable sources mark the run incomplete. Entries listed as `not_indexed` have no active snapshot on this installation. Accepted sources, passages and existing citation IDs stay available while changes await review.

### PostgreSQL 17 manual freshness

Use `python scripts/postgres_manual_refresh.py --baseline-dir /path/to/archived-html --state-dir /path/to/private-review --limit 48` with the local database URL. Each original HTML file must be named with the SHA-256 recorded in the active index, followed by `.html`.

The command rotates through the oldest checked sources and reads at most the specified number per run. It verifies the official versioned URL and page identity, compares the manual article with the archived original, and records each outcome in the local `checks.sqlite` ledger. The article comparison includes code whitespace, links and citation anchors. Site announcements and navigation are outside the comparison. Changed article HTML is saved by digest under `candidates/` for review. Invalid, missing or unreachable sources yield a nonzero exit status. The running tutor keeps its existing passages and citations throughout the check.

To inspect pending differences, query the most recent result for each URL and accepted hash, for example:

```sql
SELECT url, accepted, checked, result
FROM (
  SELECT *, row_number() OVER (PARTITION BY url, accepted ORDER BY checked DESC) AS latest
  FROM checks
)
WHERE latest = 1 AND json_extract(result, '$.status') = 'article_changed';
```
