# Bounded UX implementation plan — Phase 9

2026-10-04. Implements the [Quiet Workspace recommendation](../design/DESIGN-DECISION.md), [information architecture](UX-ARCHITECTURE.md) and [design-system contract](../design/DESIGN-SYSTEM.md). This plan is not evidence that fixes have shipped. All stages below start **not implemented**, except explicitly preserved existing behavior. The original design-plan phases remain authoritative: primitives first, then bounded experience work, accessibility/regressions, before/after validation, performance and cleanup.

## Execution contract

For each slice: inspect current code and applicable skills, reproduce the affected flow on a disposable database, state problem/files, identify learning invariants, then make the smallest coherent change. Run relevant unit/browser tests, lint/types and production build when production code changes. Inspect screenshots and actual keyboard/narrow behavior. Record observed results and failures in the shared handoff, commit explicit files and push both private variants after refreshing the private snapshot. Sanitize the second checkout; never include real course material, acquisition scripts, credentials or learner data there. Preserve unrelated working changes.

Do not treat compilation, axe, mock responses or a design score as proof of usability or learning quality. No new libraries are needed. Use the existing recovery identities, tokens, components, routes and backend ownership. Do not transplant prototype scripts into production. Any architectural discovery is documented before expanding scope.

## First production slice

**Next: Stage 1a under Phase 10.** Inspect rendered Textarea and inline-code specimens in current light/dark/system themes. Proposed files are `frontend/src/index.css`, `frontend/src/components/ui/textarea.tsx` and focused verification. Reuse the existing semantic palette and add only missing roles with measured values. Do not combine navigation, a new heading API, all error styles or the mastery investigation into this commit. If the control boundary is not necessary in a particular rendering, preserve decorative separation rather than darkening every border.

The broader specification includes an error role; adopt it only with a real error-state caller and verified text/surface pairing, not an unused palette addition. This boundary keeps the first implementation coherent while leaving full design-system adoption explicit.

## Required integrated acceptance matrix

| Journey / condition | Evidence to retain | Must remain invariant |
|---|---|---|
| Start chosen topic / empty area | First-use path, readable explanation before question, explicit empty preparation path | No unrelated default lesson; backend target policy unchanged |
| Incorrect answer / confused learner | Actual correction, hint/simpler/detail request and same-topic continuation | No forced confidence; no invented praise, grade or mastery evidence |
| Pause after 30seconds / resume | Same server checkpoint, draft scope, visible next action; screenshot and request trace | Pause not End; no generation on simple route return |
| Refresh / Back / Forward / second context | Retained server state and honest browser-draft boundary | No duplicate submissions; lost browser draft not claimed durable |
| Slow/error/interrupted model or grading | Existing partial text, exact original answer, safe retry/lookup/stop | No blind resend, no hosted promotion, late result cannot overwrite another target |
| Notebook run / check / return | Code and dataset identity, exact checked snapshot, return context | Code edits invalidate stale check; execution not equivalent to project completion |
| Skip/clear/later/change topic | Label/Undo and explicit consequences; existing context recoverable as promised | Self-label never changes competency; current session termination disclosed |
| Settings / adaptation | Actual effect timing, reason and learner choice; clear units | No silent preferences, enrollment, modality or model changes |
| Keyboard / screen reader / sensory | Focus, headings, control pattern, announcements; physical audio separately | No hidden exit/help, autoplay or obscured focus |
| Responsive / theme / zoom |320/390/800/1280/1920px as relevant;200% text; browser zoom; both/system themes | No clipped labels or removed features; contained technical overflow explicit |
| Delayed return / human comprehension | Owner identifies topic, next action, saved work and recovery without coaching | Simulated profile is not human acceptance; a fresh context is not a real week away |

## Verification commands and publication

Use existing scripts rather than adding infrastructure. From `frontend`, run selected `pnpm exec vitest run <affected tests>`, `pnpm lint`, `pnpm exec tsc -b`, `pnpm build`, and relevant `pnpm exec playwright test <journeys>`. Standard browser journeys start disposable services; do not attach them to the live learner database. Prototype comparison uses its standalone config and cannot verify production changes. For any eventual backend change, use the project's uv runtime, affected pytest suites, ruff/mypy and required migration checks. Inspect command failures before broadening tests.

Each completed slice records problem, files, exact tests/visual/keyboard/responsive evidence, remaining issues and next step. Obtain code/pedagogy review when learning/recovery behavior is involved. Keep original and sanitized commits separate; use the publication guard and refresh private database snapshot under the established owner policy. A failed second push is not completion.

## Finish gates, not shortcuts

After bounded implementation: add stable visual baselines for Home, lesson, question, feedback, progress, settings and mobile lesson; compare unexpected changes manually. Repeat the original personas and record measured steps/re-entry/errors, separately from subjective preferences, in `docs/ux/UX-BEFORE-AFTER.md`. Measure production bundle/route load, layout shifts and unnecessary renders before cleanup. Remove only proven dead code/experiments after validation; retain design rationale. Existing bundle warnings are not resolved by this plan.

Phase 9 checked current paths and existing tests against this sequence; no application code or learning logic changed. Human acceptance, real audio, metric design and full material coverage remain open. Acquisition and unrelated runtime-extension queues stay parked while the owner-directed UX phase work continues.
