# Slice: backup-restore (P5, 2026-09-20)

**Story.** The learner can put the whole installation's learning data into one file and bring it back on an empty machine — competency evidence, FSRS state, preferences, plans/checkpoints, vocabulary, curriculum drafts and published lessons, source references — without ever risking the live installation. `scripts/export.py` / `wipe.py` (one learner's rows, JSON) are unchanged; they are portability, not recovery.
**In/out.** `backend/app/db/backup.py`: `create_backup(sync_url, out, scope, transcripts_dir, settings_snapshot)` → zip with `manifest.json` (+ `manifest.sha256`), `db/tutor.sqlite3` (consistent snapshot via the SQLite online-backup API, WAL folded, `VACUUM`ed), optional `transcripts/<sha>.json`; `inspect_backup(path)` validates and verifies every checksum without writing; `restore_backup(path, target)` restores into an **empty** target (`<target>/data/dev.db`, `data/transcripts/`, `backup-manifest.json`, `RESTORE-NOTES.md`). CLI `scripts/backup.py create|inspect|restore`; `make backup out=… [scope=learner|full] [transcripts=1]`, `make backup-inspect f=…`, `make backup-restore f=… target=…`.
**Manifest v1.** `format audhs-tutor-backup`, `version 1`, `purpose private-recovery`, `scope`, `created_at`, `encryption: none`, `app.{alembic_revision, alembic_head}`, `database.tables{name: rows}`, `index.collections[]` (collection, embedding registry id/version, dims, chunk count) + the explicit recovery step (`scripts/reindex.py --embedding-version N`; vectors are never backed up), `config` = reconstruction settings only (routing profile, embed model, hosts, roots, cache dir, budget — `anthropic_api_key`/`hf_token` are excluded by name), `sources.documents[]` (uri, course › section › lecture, title, latest content hash — originals are referenced, never copied), `excluded[]`, `files[]{path, sha256, size}`.
**Scopes.** `learner` (default): the corpus *text* tables `chunk`, `chunk_provenance`, `index_state` are deleted from the snapshot copy; `document`/`document_version` stay as source references (re-ingest is idempotent by content hash; chunk ids change, so objects citing old passages show the "no longer in the corpus" fallback until re-published). `full`: everything, for the owner's private reinstall — includes purchased course text; the CLI says so. **Policy:** the `rag-ingest` rule ("no export/share of corpus content") is kept; a private backup is not sharing, and the default scope does not contain course text. Whether `full` may become the default is the owner's call (recorded in `docs/IMPROVEMENT-PLAN.md`).
**Restore safety.** Refuses: an occupied target, a non-zip, a missing/mismatching manifest checksum, unknown format/version/scope, members not listed in the manifest, listed assets missing from the archive, any path that is absolute / contains `..` / backslashes / drive letters / is outside the closed list (`db/tutor.sqlite3`, `transcripts/<hex>.json`), symlink members, size mismatches, a snapshot whose Alembic revision this build does not know, a snapshot failing `PRAGMA integrity_check`. Members are streamed (never `extractall`) into a staging folder next to the target with checksums verified during the write; migrations run **inside the staging copy** (`upgrade_to_head`), then the folder is renamed into place. Any failure removes the staging folder; the target and the live installation are untouched. No archive-provided code is ever executed; archive paths are never trusted.
**Encryption.** Optional since 2026-09-21 (ADR-0012 accepted `cryptography`): `docs/slices/encrypted-backups.md`. A plain archive is integrity-checked (sha256) but not confidential; its manifest says `encryption: none` and the CLI prints `not encrypted`.
**Donor.** `lernapp-updates/backend/app/services/transfer.py` @ `8b27582` (2026-09-10) — principles adapted (known-tables-only, empty-installation rule, staged materialisation with rollback, no SQL/pickle in archives); no code copied (the donor is PostgreSQL + Fernet; no licence file in the donor repo — treat as all-rights-reserved).
**Events.** None. **Mode/energy.** n/a. **Accessibility.** CLI only in this version (a Settings › Data screen is a follow-up).
**Verified by.** `tests/test_backup_restore.py` (round trip of **every table** on a head-revision database filled by reflection; secrets absent from the archive bytes; learner scope drops corpus text and keeps references; occupied target; corrupted member; tampered manifest; unsupported version/format; unlisted member; `..`/absolute paths; missing asset; unknown revision; symlink member; partial failure → rollback; refuse overwrite; inspect writes nothing) and the CLI walked on a scratch database (create learner + full, inspect, restore, second restore refused).
