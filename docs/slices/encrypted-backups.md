# Slice: encrypted-backups (ADR-0012, 2026-09-21)

**Story.** A backup can leave the encrypted disk it was made on — a USB stick, another machine — without exposing the learner's evidence, preferences or (in `full` scope) purchased course text. The owner chooses a password when creating it; nothing stores that password, and losing it means losing the backup (stated on creation).
**In/out.** `backend/app/db/backup_crypto.py`: an envelope, not a whole-file cipher. `MAGIC | u32 header length | header JSON | chunks…`; header = format/version, `scrypt` parameters (`n=2^17, r=8, p=1`, 16-byte salt), cipher `aes-256-gcm`, chunk size (1 MiB), 8-byte nonce prefix, `inner: zip` — public, never key or password. Each chunk `u32 ciphertext length | u8 final flag | ciphertext`, nonce = prefix ‖ chunk index, AAD = sha256(header) ‖ index ‖ final flag: a chunk cannot be reordered, duplicated, dropped or moved between files; a header edit fails every chunk; a missing final chunk or trailing bytes is refused as truncation/tampering. Memory is bounded by the chunk size on both sides (`MAX_CHUNK` 8 MiB when reading), a crafted header cannot demand more than `n=2^18, r=8` (≈ 256 MiB) before we refuse to derive, the header is capped at 4 KiB, chunk count at 2^32. Passwords are NFC-normalised UTF-8; the empty password is refused. `encrypt_file`/`decrypt_file` create their output exclusively (0600) and remove it on any failure; wrong password and corruption are one refusal (GCM tag). `backup.create_backup(..., password=…)` writes the zip in the staging dir, wraps it, and the manifest inside says `encryption: aes-256-gcm+scrypt envelope v1`; `inspect_backup`/`restore_backup(..., password=…)` detect the magic, refuse without a password, decrypt into a private 0600 copy **next to the archive** (`.<name>.decrypting-*`, same volume, never the shared system temp; restore: inside its `.restoring-` staging dir next to the target) after a free-space check, and remove it afterwards — an encrypted inspect needs the archive's size in free space, a restore roughly twice. CLI `scripts/backup.py create --encrypt [--password-file F]` (prompt + confirmation otherwise, 12+ characters recommended), `inspect`/`restore` prompt only when the file is encrypted; `make backup … encrypt=1 [pwfile=…]`, `make backup-inspect/-restore … pwfile=…`.
**Events.** None (operator tooling; no learner-state change).
**Mode/energy.** n/a.
**Accessibility.** CLI only; the refusal messages say what to do.
**Verified by.** `tests/test_backup_encrypted.py` (7): create → inspect → restore round trip with every table equal, mode 0600, header without secrets, refusal without a password; wrong password refused with nothing left behind (no target, no staging, empty password refused); a flipped byte in the header, the body and the last byte each refused; truncation at a chunk boundary and inside a chunk, reordered chunks, a duplicated chunk, a flipped final flag on a middle and on the last chunk, a truncated file re-marked as complete, a tampered length field and trailing data each refused with the specific message (damage after the first chunk names the chunk and says the password was accepted); crafted headers (`n=2^30`, unknown version, short salt) refused before any key derivation, an "innocent" header edit (`inner: tar`) fails on the first chunk's tag; plain zips still work and a plain zip is not decryptable. the same CLI journey runs in a subprocess (`test_cli_round_trip_in_a_fresh_process`). Locally on 2026-09-21: `make lint` green; backend 252.
**Found on the way (P5 bug, fixed).** `scripts/backup.py restore` refused *every* real backup with "unknown table 'assessment_rubric'": the restore's schema allow-list comes from `Base.metadata`, and in a fresh CLI process nothing had imported `app.db.models`, so the metadata was empty (the pytest suite never saw it because the app is imported elsewhere). `backup.py` now imports the models module itself, and `test_cli_round_trip_in_a_fresh_process` runs the CLI in a subprocess (create → inspect → wrong password → restore) so the fresh-process path stays covered.
**Review (code-reviewer, 2026-09-21).** Blocker fixed (CLI test scope). Majors fixed: decrypted copy now next to the archive instead of `$TMPDIR`, free-space check before decrypting and `OSError` reported as a refusal, final-flag and length-field tampering tested. Minors fixed: chunk-aware error message, non-Unicode passwords and non-UTF-8 password files refused, password-file permission note, no prompt without a terminal, `encrypt=1|yes|true` only, missing archive refused by restore. Recorded: a SIGKILL mid-restore can leave `.<target>.restoring-*/archive.decrypted.zip` (plaintext) next to the target — documented in RECOVERY.md.
**Open / recorded.** Not a key-recovery scheme: no password → no data (by design, ADR-0012). No key stretching cost calibration per machine (fixed `n`). The old plain zips stay readable and are still labelled `not encrypted`. Not done: a `.zip.enc` hint in `RESTORE-NOTES.md` beyond the manifest label; a `--rekey` command.
