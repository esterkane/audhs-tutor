# C6 Resume and new-session intent

Before implementation: Home's combined Resume/Start card exposes two competing actions. More importantly, Home.begin posts /sessions even with a current session; kernel.session.start creates another row without ending the old one, and /sessions/current selects only the latest unended row. Merely relabeling this path would preserve context loss. SelectedLesson already implements the explicit eligibility-check → Keep current or End and start flow, with failure recovery.

Bounded change: separate a short Continue action and named saved topic/next step from new-session preparation. While a current session exists, Home's explicit start/revisit intent routes to SelectedLesson with the actual selected skill rather than posting another session. No session ends from opening the disclosure or selecting a target. With no current session, existing start/review-offer behavior remains. If no target is eligible, retain area preparation; review-only continuation remains through the current plan and a new session can be started after explicitly finishing it. Do not add a second lifecycle implementation or fabricate multiple paused contexts.

Likely files: Home.tsx and its relevant browser/component selectors/tests, focused intent test. No backend schema/learning-kernel/provider change. Verify no writes on Continue/disclosure/switch intent, authoritative phase resume, selected lesson confirmation, unchanged fresh start and review offer, error/empty preparation, keyboard and responsive flow.
