# Focused authoring and backed-up course retirement

The active learning catalogue focuses on Elasticsearch, vector search, Supabase, PostgreSQL, Qdrant and Kubernetes. New material starts from notes or optional uploads, proceeds through Source → Research → Write → Review, and becomes a lesson only after explicit activation. Six small build/test/reflection projects keep application practice distinct from mastery evidence. The Supabase brief links the owner-selected project source; its conversational integration is a separate qualification task.

A learner-specific boundary retires earlier skills, drafts, review items and ordinary retrieval without deleting historical learner answers, attempts or session identities. Historical references have an explicit accuracy-review search route. Legacy automatic course/area drafting and old-answer promotion cannot bypass this boundary. An upload made after reset has a scope-specific source location, so intentionally uploading identical bytes remains possible without overwriting its earlier record. Browser authoring and companion checkpoints use scope-specific storage while retaining older recovery data.

The retired automatic-course workspace and sound visualizer no longer appear in active navigation; old workspace bookmarks open the new projects catalogue. The historical guitar preference is retained but is hidden and cannot add a planned practice block. Read-aloud, voice controls and their accessibility behavior remain available. Retired browser journeys are preserved separately rather than run against removed surfaces.

`reset_learning_focus.py` is read-only by default and requires a new external private backup before applying. `retire_course_sources.py` separately plans source retirement, requires review of an exact digest, verifies a fresh SQLite backup, deletes matching index points, clears reusable source/cached course content while keeping referenced IDs, privately retires legacy assets, and resets the map. Original files outside the active application are not moved. Private receipts support resumption; index failure leaves source content intact, and a lost receipt after database commit can be reconciled. Historical writing/record hashes are checked. Removed source tombstones are excluded from document lists, retrieval rebuilding and passage viewing.

Verification includes isolated owner/version/evidence tests, source retirement and failure/retry tests, a disposable vector-index check, a full-copy private rehearsal, and a dedicated Chromium authoring/activation/study/resume journey with mobile accessibility checks. The test lesson is newly written from a synthetic upload, not imported from the earlier catalogue. It exercises explicit author acceptance, not automatic factual certification.

The dedicated `playwright.focus.config.ts` uses its own disposable database. CI runs it after the standard active journeys. Databases, receipts, backups, uploads, private assets and machine configuration are excluded from publication. The optional project model bridge and its unqualified outputs are not included in this release.

Final local gates: 2,477 backend tests passed (one skipped), 807 UI tests passed, strict mypy passed on 322 source files, and TypeScript/ESLint checks passed. Four active navigation/audio/heading browser cases and the dedicated full focused authoring/study/resume case passed. The full focused case includes a long upload filename, preserved research and notes, mobile overflow/axe checks, and retention without automatic reuse of an older browser companion checkpoint.

Asset retirement preflights write/rename access and requires a private backup on the application filesystem. Moves use atomic rename only; a permission failure cannot trigger a partial copy/delete fallback. Stop the application API before applying and restart only after receipt/history checks pass.
