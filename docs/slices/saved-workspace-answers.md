# Saved workspace tutor answers

QA01 first integration: completed notebook/StudyTutor and playground replies are stored in learner-scoped SQLite with exact returned text, bounded supplied request context and model/prompt metadata. The UI distinguishes saved from delivered-but-unsaved. This does not certify correctness or change learning evidence; no dependency or hosted call added.

The immutable store deduplicates learner/turn writes and rejects a conflicting payload. It explicitly commits after existing trace/event transactions; failures roll back the save and return the generated text with a safe warning. No SQL parameter logging. The route and store validate session ownership. Only nonempty completed replies enter this table; no partial stream is integrated yet.

Scope limits: request-level inference deduplication and recoverable save retry remain pending, as do lesson/voice/representation/assessment integrations, stable course/step identities, real-question vs internal prompt separation, local search and suggestions. Workspace snapshots are context-dependent private history, not reusable generic FAQ or corpus evidence. Browser Stop may discard a reply while the server finishes; a saved generated answer is not proof of delivery, reading or listening. The current schema's complete-only table must gain explicit states before partials are supported.

Backup/export/wipe follow the existing learner-scoped table mechanism. Bounded workspace text/code/output may contain material supplied by the learner; no full corpus passage snapshot or system prompt is copied. Private backups remain private and sanitized publication excludes runtime databases.
