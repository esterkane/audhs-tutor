# Publication index guard

The public publication check now inspects staged Git blobs instead of worktree files. Unstaged sanitization cannot hide private staged bytes; deleted-but-still-staged files remain checked. Detect runtime paths including private-state, SQLite signatures, unresolved merges, unreviewed submodules and owner-prohibited source identifiers in paths/content (case-insensitive tokens, including generated API comments). Hash identifiers in the public policy so the prohibited names themselves are not introduced by the guard. Diagnostics omit matched content.

Apply only to the public/sanitized repository. Private archive deliberately retains private-state and is not an eligible public publication tree. A failed command must terminate the publication sequence (`set -e` or checked subprocess return codes); a checker cannot stop a caller that ignores its failure. This does not scan old remote history or certify copyright, rights or all secrets; existing explicit review remains required.

Tests use synthetic identifiers and disposable Git indexes: staged database with clean unstaged replacement must fail, staging the clean content passes; private compressed snapshot paths fail. Current public index must pass before commit/push. Three isolated regression tests pass in both checkouts, full lint/types pass, and the current staged public index passes the new guard. Independent code review found no blockers/majors. No runtime app, schema or UI change; prior 430-backend/202-frontend suite results remain historical, not rerun for this script-only slice.
