# Slice: session-transitions (P1, 2026-09-20)

**Story.** The learner moves through the planned blocks — movement → review → new material → challenge → interleaved review → language/guitar → recap — and every screen, reload and resume shows the *same* block, because the server owns the block state. A double-click, a retry after a dropped connection or a stale render can never start a block twice, end it twice or overwrite the checkpoint with an old index (review findings 1 and the `_phase` mapping).
**In/out.** `kernel/blocks.py`: `BlockState` (`block_index`, `block`, `block_id = <session>:<index>`, `block_status running|ended`, `block_started_at`, `phase`, `skill_id`, `next_index`, `plan_version`, `timer_extension_min`, `plan_complete`, `allowed`, `message`) derived from the checkpoint; `start(index)` (idempotent when already running; refuses while another block runs), `end(index, reason, …)` (idempotent; grasp check for early switches out of new material via `planner.can_switch_early`; `actual_min` measured on the server from `block_started_at` when the client sends none), `advance(from_index, reason, …)` = end + start next in one call with `from_index` as the idempotency key ("already advanced" on a retry), `extend`, `end_running` (session end closes a half-open block with `reason=session_end`), `bump_plan_version` (accepted / undone re-plan). Phase map: `movement_primer`/`domain_switch` → `practice`, `retrieval`/`interleaved_review` → `review`, `new_material` → `teach`, `challenge`, `recap`. The **active skill** is persisted in the checkpoint at session start and set to a block's node when a new-material/challenge block starts; `SessionOut.next_skill` stays a recommendation. The tutor turn now *merges* into the checkpoint (it used to overwrite it and lose the block). API: `GET /api/plan/blocks/state`, `POST /api/plan/blocks/{start,end,next,extend}` → `BlockState`; `SessionOut.state`. Frontend: `useBlockTransition()` (one in-flight transition, result written into the cached session), `routeForPhase()`, `SessionBody` keyed by `block_id`+`plan_version` (a new block starts with fresh hint/grasp/phase state), `StartCard` when nothing runs, Home's "Which first?" starts the chosen block (`review` → first review block, `learn` → first non-review block; blocks before it are passed over, not ended), Resume routes by server phase, `Review` and `Recap` participate in the plan (Review: "Continue the plan" → `next`; "Stop here" → `end(save_and_stop)`; session end closes the recap block).
**Events.** Exactly one `block_started` and one `block_ended` per block (`docs/EVENT-SCHEMA.md`: `reason ∈ finished|switch_early|skipped|save_and_stop|session_end`, `actual_min` server-measured). `started` unchanged. No new verbs.
**Mode/energy.** Low-capacity / energy ≤ 2 plans are already minimal (retrieval + recap); the offer recommends review first. Energy check-in re-plans from the current block; an accepted card bumps `plan_version` so the screen refetches and the timer re-derives its deadline. Domain switches still happen only at block boundaries.
**Accessibility.** Buttons disable while a transition is pending; refusals (grasp check, "still running") are `role=status` text with the next step; nothing moves automatically except the route change the learner triggered.
**Verified by.** `tests/test_session_transitions.py`: full journey with a `GET /sessions/current` "reload" at every boundary and exactly one start/end event per block; double-click / retry idempotency (start, next, end); grasp-check refusal leaves the block running; save-and-stop and session end close the block once; timer extension survives a tutor turn (checkpoint merge); review-first semantics; low-capacity path; per-card `confidence_pre` on `reviewed`; vocab decks never `next_skill`. `Session.test.tsx` (server block rendered, timer from server start time, `+5` → `/blocks/extend`, double-click → one `/blocks/next`, StartCard → chosen block), `Review.test.tsx`, `Home.test.tsx`.
**Open.** Browser journey tests need Playwright (not an approved dependency — decision recorded in `docs/IMPROVEMENT-PLAN.md`). Draft answers in the assess panel are still component state (lost on reload; nothing is submitted silently).
**Review fixes (code-reviewer + pedagogy-reviewer, 2026-09-20).** Blockers: (1) the checkpoint endpoint could rewrite server-owned fields (`block_index`, `block_status`, `plan_version`, …) through `extra` or a stale `block_index` — they are now `RESERVED_CHECKPOINT_KEYS` (stripped from `extra`), a stale `block_index` is a `409 stale_block`, and `phase` is validated against the running block (`teach|assess` inside new material, otherwise the block's own phase → `409 invalid_phase`); (2) concurrent requests could both pass the read-check → transitions are serialised per session (`api.plan.session_lock`, an `asyncio.Lock` per session on `app.state`, no module singleton) and the event is committed *together* with the checkpoint (`emit(commit=False)` + one commit); the checkpoint is now **one row per session updated in place** (deterministic `load_checkpoint`; the old append-then-prune could pick the wrong row within a millisecond); (3) an accepted energy-1 re-plan dropped the running optional/challenge block — `planner.replan` never removes the first block of the re-planned tail, `block_type` is persisted at start and a mismatch is treated as ended (never a dead end), and `SessionBody` is keyed by `block_id` only (an accepted re-plan no longer wipes the screen). Majors: leaving new material is allowed only with recall evidence — the client's `grasp_passed` is a hint, the kernel reads `attempted` events on the active skill since the block started (survives reloads), and this holds for `finished` too (only Save & stop / session end bypass it, with a literal message); `reason` is a closed set on both endpoints (`superseded` removed); `advance(from_index=None)` after an ended block continues with the next one; the StartCard offers *Continue: <next block>* after a stop instead of restarting the plan and shows refusals as text; "Which first?" labels say what starts and what is skipped (`Move (5 min), then new material: X — skips …`, `Review … — skips Move`) and the plan strip renders passed-over blocks as "not started" (dashed), never struck through (`first_started_index`); the session header names the **active** skill (`SessionOut.active_skill`), not the map's recommendation; a tutor question about another skill no longer re-targets a running new-material/challenge block; `bump_plan_version` skips ended sessions; `extend` goes through the in-flight dedupe and the timer's buttons wait for a pending transition; `Review` "Stop here" returns early while pending and catches transition errors; `block_ended.result.timer_extension_min` records soft-timer extensions. New tests: concurrent `next` ×3 → one start; checkpoint cannot move/relabel the block; `finished` without evidence refused, allowed after an attempt; energy-1 re-plan keeps the running block and bumps `plan_version` (accept via `adaptation.decide`); continue after stop, start after session end refused; SoftTimer hides when the extension arrives; Home Resume routes by phase.
