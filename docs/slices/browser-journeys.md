# Slice: browser-journeys (ADR-0013 follow-up 1, 2026-09-21)

**Story.** The flows the kernel guarantees on paper — the server owns the block, the review screen collects confidence before revealing, "Stop here" keeps the plan resumable — are exercised in a real browser against the real stack, so a regression in routing, query caching or client state is caught before the owner sits down to learn. Component tests keep mocking fetch; these journeys do not mock anything.
**In/out.** `frontend/playwright.config.ts` (`testDir: e2e`, one worker, serial, Chromium only, `reducedMotion: reduce`, traces/screenshots on failure) starts **two** web servers and waits for each on its own URL: `make sandbox-backend` (seeds + migrates a **fresh `data/sandbox.db`** on every run — a guard refuses any `SANDBOX_DB` ending in `dev.db`; `ANTHROPIC_API_KEY` empty and `DAILY_BUDGET_USD=0`, so no hosted call can happen; readiness = `/api/health`) and `make sandbox-frontend` (Vite bound to 127.0.0.1, readiness = the page). `reuseExistingServer: false`: a sandbox someone left running holds walk-through state, so Playwright fails fast on a busy port rather than testing on it. Ports come from `SANDBOX_API_PORT`/`SANDBOX_UI_PORT` (defaults 8010/5174) and all URLs use 127.0.0.1 (IPv6-first `localhost` resolution is a known flake). `frontend/e2e/helpers.ts` (API base, end-open-session guard, start-from-Home, reach-the-learn-block, `finishReview` — rates away cards an earlier journey left due, because a session end schedules a review card for the active skill and the journeys share one database). `frontend/e2e/session-journeys.spec.ts`: (1) start → "Which first?" → movement block → reload → skip → review done → reload → continue → learn → reload → a second tab shows the same block; the server state is asserted through `GET /api/sessions/current` at each boundary; (2) one due card made through public routes only (first attempt on a **journey-specific skill** creates the item — `next_item` rotates mcq → cloze → explain_back per skill and the third kind needs a local model the CI runner lacks, so the helper asserts the kind is mcq/cloze — then a rating with the API's `as_of` time travel three days back) → Home offers review first → "Show answer" is disabled until a confidence is chosen → rate → "n of n due items reviewed" → continue → learn block; (3) review first → "Stop here (save progress)" → recap; a **fresh browser context** from the `browser` fixture (no localStorage; `reducedMotion` and `baseURL` carried over; closed in `finally`) → Home "Resume session" → "Continue the plan?" → "Continue: New material" → learn → reload. (4) `e2e/code-editor.spec.ts`, see `docs/slices/code-editor.md`; (5–7) `e2e/code-run-offline.spec.ts`, see `docs/slices/local-pyodide.md`. Every test ends the open session through the API before and after. `make test-e2e`, `pnpm test:e2e`; `tsconfig.e2e.json` is referenced from `tsconfig.json` so `make lint` type-checks the journeys; `pnpm lint` (`eslint .`) covers `e2e` and both configs; vitest keeps its default excludes plus `e2e/**`. CI job `journeys` (ubuntu, `playwright install --with-deps chromium`, traces uploaded on failure).
**Events.** None new; the journeys observe `block_started`/`block_ended`/`reviewed` only through the screens and `SessionOut.state`.
**Mode/energy.** Steady · energy 3 only (the sandbox's default plan: move → warm-up review → new material → recap). Low-capacity and energy re-plan journeys are not covered here (component tests cover them).
**Accessibility.** Every control is located by role + accessible name (the confidence fieldset by its legend); `getByText` is used only for status copy. A journey fails when a control loses its name.
**Verified by.** `make test-e2e`: 7 passed (~25 s) on the owner's Mac, repeatedly, ports released afterwards; `make lint` green with the e2e sources. **Not verified:** the CI job has not run yet (it needs the repository's first push after this commit) — treat it as unproven until the first green run.
