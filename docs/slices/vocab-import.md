# Slice: vocab-import (P3, 2026-09-20)

**Story.** The learner imports a CSV vocabulary list: sees the detected columns and every row with a status (new / already a card / duplicate in the file / invalid with the reason), fixes or removes rows, chooses language and whether to also create reverse cards, and confirms explicitly. Re-importing the same file adds nothing and never resets a schedule.
**Donor provenance.** Ported (logic, not code) from `~/projects/lernapp-updates @ c2bf79f8277dc70ef4e0e4bb1b89509c6f1c5f9f` — `backend/app/services/vocab.py::parse_csv` (BOM-tolerant, `,`/`;` sniffing, optional header) and `services/vocab_import.py::import_items` (identity = normalised word + meaning, per-owner dedupe, existing schedules untouched); the same file is *untracked* in `~/projects/lernapp` with identical content. No dependency implications (stdlib `csv`). **Not ported:** the PDF glossary parser — it needs `pypdfium2` (not in ARCHITECTURE.md; not approved) and only handles one layout (bold term + colon); the tutor's `pypdf` cannot read font weights. Decision for the owner: approve `pypdfium2` for a layout-specific glossary importer, or keep CSV (export the glossary as CSV). Until then the UI says so.
**In/out.** `kernel/vocab_import.py`: `parse_csv(bytes) → Preview` (≤ 2 MB, ≤ 2000 rows, delimiter `,;\t|`, header aliases in DE/EN incl. `front/back`, `term/definition`; positional fallback = word, translation, example; word ≤ 120 / translation ≤ 200 / example ≤ 300; in-file duplicates by normalised word+meaning; problems reported per row, never raised), `preview(db, learner, lang, data, reverse)` marks rows whose card exists, `import_rows(...)` → `added / reverse_added / skipped_existing / invalid`, one transaction (rollback on any failure), idempotent by identity, `source`/`source_row` attribution stored on the card. API `POST /api/vocab/import/preview` (`lang, csv_text, reverse`) and `POST /api/vocab/import` (`lang, rows[], reverse, source`). UI `/vocab` → "Import a CSV list": file picker or paste, preview table (editable word/translation/example cells, remove-row button, status column, per-row problem text), language + "also create reverse cards", counts line, explicit "Import N cards" button, result line, empty and error states; keyboard reachable (native inputs/buttons in a table).
**Events.** None (see vocab-identity). Imports show up as cards and, once reviewed, as `reviewed` events.
**Mode/energy.** Not session-facing; the language block picks the cards up through the existing due queue.
**Accessibility.** Table with headers, `role=status` counts, `role=alert` errors; the confirm button names the count; no drag-and-drop-only path.
**Verified by.** `tests/test_vocab_import.py` (parser variants, statuses, limits, idempotent re-import, schedule preserved after a review, reverse only when selected, invalid rows counted, atomicity on a forced failure, routes) and `frontend/src/features/practice/VocabImport.test.tsx` (preview → edit → confirm → counts; empty state).
**Open.** PDF glossary import (dependency decision above). Per-card source links open nothing yet (P4 source viewer).
**Review fixes (code-reviewer + pedagogy-reviewer, 2026-09-20).** Blockers: the delimiter sniff counted separators inside quoted cells (`"Wort, das";Bedeutung` flipped to `,`) — it now picks the delimiter with the most consistent ≥ 2-column shape via `csv.reader`; per-row full-deck scans inside the import transaction — `practice.deck_index()` is built once per import and `add_vocab(index=…)`/`ensure_item(lookup=False)` make each row O(1). Majors: `norm_text` is NFC + `lower()` (NFD `é` == NFC `é`; `Maße` ≠ `Masse`), mirrored in the migration; `:` inside a word is percent-escaped in the ref and legacy rows are recognised by the missing `direction`; a preview no longer creates a deck node (`existing_refs` looks the deck up); under "also reverse" a forward-existing row is `reverse_only` ("already a card — only the reverse card is new") and the import reports `reverse_skipped`; in-file duplicates are counted; language/direction are locked after a preview ("Start over" to change); editing a row's word/translation re-derives its status (server has the final say); the migration is exercised on a disposable DB (upgrade rewrites the ref, FSRS rows byte-identical, downgrade restores). Minors: `lang` validated (`^[a-z]{2,3}(-…)?$`, stripped/lowered in `deck_slug`); language-code headers map the deck's language to *word*; cell limits mirrored in the UI; `/vocab` collapses "Add one card" and "Import a CSV list"; removed rows can be undone; datalist of common languages; the counts line is no longer a live region; axe + failure-path tests; router thin (`practice.card_due`, `PreviewRowOut.model_validate`).
