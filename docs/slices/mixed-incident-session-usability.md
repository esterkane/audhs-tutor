The deployed release's backend CI failed at import sorting in the learning-project migration. The import-group change is formatting only; schema operations and data are unchanged. The complete backend lint/format scope is now checked, including migrations, alongside application typing and affected tests.

Reported mixed PostgreSQL errors now compose reviewed diagnostic plans rather than send that recognized combination back to free-form generation. Each boundary retains its own explanation; the reply asks which statement, role and time belongs to each error instead of assuming one root cause or a successful earlier fix. Duplicate read-only queries are removed and sources retained. Code-only missing-relation/column reports and combinations with the ambiguous privilege code use the same reviewed plans. Mixed errors do not create root causes, evidence or mastery updates. Unrecognized failure families still require broader local-model qualification.

Plan context identifies the recorded later start, earlier blocks say skipped at start, and shared audio settings replace duplicate reader/voice panels. Genuine recovery and storage-loss warnings remain available; an ordinary in-flight submission does not look like a lost-result recovery. The larger navigation and single-More composition redesign is tracked separately in the design reconciliation.
