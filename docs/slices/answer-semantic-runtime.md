# Scoped local semantic answer retrieval

Workspace tutor requests first use literal saved-answer lookup; if fewer than two matches exist, add local semantic candidates from the private cache. A two-second optional lookup budget falls back to lexical/no-memory generation.
Candidate ownership, task/context and exact supplied work are filtered before the bounded newest-256 pool. Hidden/incorrect/outdated and memory-derived answers are excluded; current rows and cache fingerprints must be rechecked after embedding. Similarity is a relevance heuristic, never correctness or exact-reuse authority.
Completed workspace replies schedule bounded local index population after delivery using a separate DB session. Missing models/indexing failures leave delivered answers intact. Manual indexing remains available for backlog/rebuild.
No model downloads or paid embeddings. One bounded query embedding only; vectors for prior answers are generated in the separate indexing path. Historical provenance continues to be saved/visible and does not become corpus evidence.
Verification: 464 backend tests before numeric review fix; focused semantic/memory regressions after fix, lint/types passed. Review fixed candidate norm underflow with stable normalization; tiny-vector API test verifies generation still succeeds. SQL exclusions before limit tested with 260 newer derived replies. Re-review clear. A disposable real local smoke indexed one synthetic answer; literal search missed its paraphrase and semantic lookup found it in 33 ms (single trial, excludes generation). The 0.65 relevance cutoff is provisional, not a calibrated confidence score; small synthetic retrieval evidence does not establish general teaching quality.
