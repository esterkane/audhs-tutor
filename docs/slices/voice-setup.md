# Slice: voice-setup (P9, 2026-09-20)

**Story.** Before anything speaks or listens, the learner sees exactly what is installed, installs what is missing with explicit clicks, verifies that the components really load, tests the microphone with a recording that is thrown away, and only then activates voice. Installed ≠ activated; nothing downloads, starts or switches by itself.
**Contradiction resolved.** CLAUDE.md/ADR-0001 say "MLX for STT/TTS" and name "Kokoro-82M persistent server". Decision: STT = the registry's MLX Whisper snapshot (`whisper-large-v3-turbo`, the same adapter ingest uses); TTS = a **Kokoro server the owner starts** (`KOKORO_URL`, OpenAI-compatible `/v1/audio/speech`, PCM out; the MLX build of kokoro-fastapi is the natural choice on this Mac); the donor's faster-whisper + Piper are not adopted. ADR-0001's wording ("MLX only for STT/TTS") should read "MLX Whisper for STT; Kokoro (server) for TTS" — owner may amend.
**Registry.** New defaults in `routing_profiles.yaml`: `kokoro-82m` (source `kokoro_server`, runtime `kokoro`, role `tts` — "pull" never downloads: it checks the server and otherwise explains how to start it, the row stays `available`), `silero-vad` (source `huggingface_file`, runtime `onnx`, role `vad`, one ONNX file into `MODELS_DIR/onnx/silero-vad/`), task `tts: {primary: kokoro-82m}`, `TaskClass.TTS`. `installed_models()` marks `kokoro` when the server answers its voices listing and `onnx:<repo>` when the file is there; reading never downloads.
**Readiness (`GET /api/voice/readiness`, `app/voice/setup.py`).** Per component `{ready, status, detail, action}`: STT (row ready + snapshot + `mlx_whisper` importable → else "pull …" / "uv sync --group stt"), TTS (server reachable → else the start command), VAD (Silero when installed, otherwise the energy detector — always usable, flagged `fallback`), tools; plus `activated`, `retain_audio`, `retention_days`, `voice`, `can_activate`, notes. **Install** = the existing registry pull jobs (Models screen). **Verify** (`POST /api/voice/verify`) loads the real STT on one second of silence and synthesizes one fixed sentence — both logged as `model_call` rows (`task stt|tts`, free). **Test** (`POST /api/voice/test-mic`, raw WAV body, mono 16 kHz, 0.5–20 s, ≤ 4 MB): transcribed, returned, **discarded** (`recording_kept: false`; the adapter writes a temp file for the duration of the call only). **Activate** (`POST /api/voice/activate {enabled}`) sets the preference `voice.enabled`; refused (409) while STT or TTS is not ready; deactivation always allowed. Preferences: `voice.enabled`, `voice.retain_audio` (default off), `voice.retention_days` (1–90, default 7), `voice.voice` (Kokoro voice id), `voice.conversation_lang` (ISO code for the language block's conversation option). Setting `VOICE_DIR` (default `./data/voice`) — owner adds `VOICE_DIR=./data/voice` to `.env.example` by hand (hook blocks edits here).
**UI.** Models screen › **Voice** card (`features/voice/VoiceSetup.tsx`): the three components with their next step, buttons "1 · Download speech recognition", optional Silero, "2 · Verify", "3 · Test my microphone (record)" → "Stop recording and transcribe", "4 · Activate voice" (disabled until `can_activate`), Deactivate; retention state in one line.
**Spike + diagnostics.** `scripts/spike_voice.py` prints the same readiness (snapshot, package, server, Silero, onnxruntime, sounddevice) with the fix per item; `--stt FILE.wav`, `--tts "text"`, `--mic 5` (needs the optional `sounddevice`) each refuse with "gate pending" when the component is missing.
