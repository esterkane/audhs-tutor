# Slice: goal-home (P4, 2026-09-20)

**Story.** Home makes the next useful action obvious: resume the running block, do a short review, or learn toward a chosen goal. The learner picks a course/goal, sees why a skill is suggested and how long the planned session will take before starting; mode and energy stay explicit and the low-capacity path stays first on low energy.
**In/out.** Preference `goal.course` (str, empty = whole map). `skill_graph.next_skill` narrows to teachable nodes of the goal course when it is set and has nodes (unknown/empty goal → whole map); when every goal node is still locked, the unlocked prerequisites *of* the goal come next, then the whole map — a locked node is never returned while an unlocked one exists. Home: a "Goal" selector (courses with published skills + "whole map"), "Next up" = the next skill's **title** (running session, else the map's `next_skill_id`) with mastery and prerequisites-met, plus the planner's scaffold ("worked example first") as an appendix — a block reason is never shown as a title; the plan preview (`GET /api/plan/preview`) with total minutes for the chosen mode/energy, optional blocks marked; a failed goal save is shown (`role=alert`); primary actions ordered Resume → short review (when due) → Start; setup (questioning style, experiment note) collapsed under "More options", whose summary line **states the current questioning style**. `socratic` is no longer persisted in the mode store: Socratic questioning is an opt-in per session, never carried over silently.
**Events.** None new (`started` carries the plan).
**Mode/energy.** Unchanged and explicit; the duration preview updates with them.
**Verified by.** `tests/test_curriculum.py::test_publish_versions_objects_and_keeps_history` (goal narrows `next_skill`; unknown goal falls back), `::test_goal_never_returns_a_locked_node`, `Home.test.tsx` (goal select + duration preview + questioning style default visible in the summary).
**Review (2026-09-20).** Fixed: goal narrowing could return a locked node while Home hard-coded "prerequisites met"; scaffold reason rendered as a skill title; persisted Socratic hidden behind "More options"; no error surface on the goal save; optional blocks unmarked in the duration preview. Recorded: the "why this skill" reason is still composed client-side (mastery + prerequisites met); a server-side `reason` field would make it one source of truth.
