# Slice: local-pyodide (ADR-0013 follow-up 4, 2026-09-21)

**Story.** The code exercise runs offline and reproducibly: the Python runtime the browser executes is a pinned Pyodide release served by this app from its own origin, installed once by an explicit script and verified against a committed manifest — never fetched from a CDN at exercise time, never silently substituted.
**In/out.** `scripts/pyodide_runtime.py install|verify` (`make pyodide`): downloads the five core files of Pyodide **0.27.8** (`pyodide.js`, `pyodide.asm.js`, `pyodide.asm.wasm`, `python_stdlib.zip`, `pyodide-lock.json`) plus the wheels the exercises need with their transitive dependencies resolved from the lock (`numpy` → one wheel, sha256 from the lock), into `frontend/public/pyodide/` (git-ignored; Vite serves it at `/pyodide/` in dev and copies it into `dist/`). `frontend/pyodide.manifest.json` (committed, 6 files, 16 MiB total) pins version + sha256 + size of every file: the first install wrote it, every later install verifies each present file against it, re-fetches only what is missing or damaged, refuses a download whose hash does not match the pin (the mismatching bytes are not kept), refuses a manifest pinning another version unless `--refresh-manifest` is passed on purpose, and refuses manifest entries the install did not produce. Downloads are https-only, atomic (temp + rename), capped at 64 MiB per file. `verify` (`make pyodide-verify`) is offline and manual — `make lint` does not run it because the frontend CI job has no runtime. The worker (`pyodide.worker.js`) loads `new URL('/pyodide/', self.location.href)`; a failed `importScripts` becomes the explicit error *"The Python runtime is not installed in this app … Run `make pyodide` once … nothing is fetched from a CDN"* (shown by the exercise as the runtime-failed alert with "Try loading the runtime again"); a version other than the pinned one is refused after load. The exercise policy text and the loading/failure copy say the runtime is served by the app from its own origin (no version number in learner-visible text: the pin lives in the script, the worker and the manifest). A failed load is not memoised in the worker and the runner discards that worker, so "Try loading the runtime again" after `make pyodide` succeeds without a reload (`runner.test.ts`). The worker accepts package *names* only (never URLs), the last path by which it could have reached a CDN. CI: `actions/cache` on `frontend/public/pyodide` keyed by the manifest hash, then `make pyodide` (downloads only what the cache lacks), before the journeys.
