# Slice: ingest-progress (course-material stage 1, 2026-09-21)

**Story.** A long ingest of a big course export no longer looks stuck on one archive: the owner sees which file (and which member of which archive) is being worked on, how many are done of how many, and — at the end — one honest outcome class per file instead of a flat "skipped" list. An interrupted run (Ctrl-C, cancel, crash) is recorded and can be resumed without redoing what it finished, without duplicating anything and without touching originals (ingest never writes to the source folders; there are no learner events in ingest at all).
**In/out.** `knowledge/ingest/service.py`: `Outcome` = `imported | unchanged | reference_only | no_content | unsupported | gated | retryable_error | access_blocked | parser_error`; `classify(exc)` maps failures to what the owner can do about them (`SkipFile` empty/no-text → `no_content`, other `SkipFile`/"unsupported file type" → `unsupported`, STT/vision missing or failed, timeouts, I/O → `retryable_error`, `PermissionError`/encrypted → `access_blocked`, everything else → `parser_error`: a claimed format that did not parse); `_gate` reasons (caption present, media off, archives off) and extraction skips (secret-looking, unsafe path) are `gated`, nested archives `unsupported`. A links list (`external-links.json`) is stored as before but marked `reference_only` (`SourceDoc.meta["reference_only"]`, `IngestResult.reference_only`) — a website link is a reference, never a failed download — and is not counted as new material. `IngestOptions.progress(IngestProgress)` is called before every file and archive member (`done/total`, `current`, `archive`, `member_done/member_total`, running outcome counts, `run_id`); `IngestOptions.should_stop()` is polled at the same points and ends the run cleanly (`report.interrupted`). Every run is recorded: `ingest_run` (src, course, options, status `running|finished|interrupted|failed|resumed`, files done/total, last uri, `resumed_from`, summary) and `ingest_run_item` (one terminal outcome per file *and* per archive member, with document/version ids; unique per run + uri). `ingest_path(..., resume_run_id=…)` loads the terminal URIs of that run **and of the runs it resumed** (the chain) and skips them (`report.resumed`); an archive whose members all finished is skipped whole. `asyncio.CancelledError`/`KeyboardInterrupt` mark the run `interrupted` and re-raise; any other exception marks it `failed`. When a resumed run finishes, the run it continued becomes `resumed` (no longer offered). `latest_resumable_run(db, src, course)`. Migration `b7d1c0a5e2f3`. Idempotency by content hash is unchanged — a resume of the same files creates no new versions. **API** (`api/corpus.py`): `POST /api/corpus/ingest/jobs` (202; one job at a time, 409 `busy`; `resume_run_id` must name an interrupted run, else 404/409) runs the ingest as an asyncio task in-process with its own session — no job service — and keeps a live snapshot on `app.state.ingest_jobs`; `GET /api/corpus/ingest/jobs/{id}` (status, progress, result or error), `POST …/cancel` (clean stop after the current file), `GET /api/corpus/ingest/runs` (recorded runs with outcome counts). `IngestDocResult.outcome`, `SkippedFile.outcome`, `summary.outcomes/run_id/interrupted/resumed`. The synchronous `POST /api/corpus/ingest` stays for small runs and tests. **CLI** (`scripts/ingest.py`): `[n/total] Section/file` per file and `[n/total] archive.zip › member i/k name` per member on stderr (`--quiet` off), one outcome per line, an outcome summary, `--resume` (newest interrupted run over the same `--src`) / `--resume-run ID`, `--runs`; Ctrl-C prints the resume command and exits 130. `make ingest src=… [course=…] [resume=1]`, `make ingest-runs`. **UI** (Corpus › Ingest): the form starts a job, shows "File n of total: …" with the archive member while it runs (`role=status`, polite), "Stop after this file", the outcome counts as a list, skipped files grouped by outcome with a one-line meaning each, and "Interrupted runs you can resume" with a Resume button; an "Index into retrieval now" checkbox (default on) lets a run store only when the embedding model is not ready (reindex later), and a run that fails before it starts — e.g. no ready embedding model — is shown as a failure with the reason, never as an empty success.
**Events.** None — ingest writes corpus tables and `model_call` rows (STT/vision), never `learning_event`; "no duplicated learner events on resume" holds by construction.
**Mode/energy.** n/a (owner tooling).
**Accessibility.** Progress and outcome text are literal (`role=status`, `aria-live=polite`); outcome groups are `<details>`; the stop button names what it does.
**Verified by.** `tests/test_ingest_progress.py`: every outcome class on one synthetic course (markdown, code, links JSON, empty CSV, `.mobi`, a `.docx` that is not a zip, an `.mp3` with media off, a zip with supported/unsupported/secret/nested members) with the exact counts and the run/item rows; progress sequence incl. archive member counts; interruption via `should_stop` after three files → `interrupted` run with the right `last_uri`, resume → the three are not re-processed (versions unchanged), the rest runs, chain-resume of a finished run is a no-op, unknown run id → `KeyError`; a `CancelledError` from the progress hook leaves the run `interrupted`; `classify` table. Route tests for the job lifecycle (start → running → finished, busy 409, cancel, runs list, resume validation). Existing ingest/media/format tests unchanged (53) — outcomes are additive. CLI smoke on a disposable DB: progress lines, outcome lines, run listing. `make migrate-check` applied `b7d1c0a5e2f3` to a snapshot of `data/dev.db`. Corpus screen test: progress line while running, outcome list and grouped skips afterwards. Browser check (sandbox stack, synthetic 4-file course under the ingest root, index off): the progress line ("File 1 of 4: 01 - Intro/001 - notes.md · so far nothing finished yet") with the Stop button, then "2 documents, 1 new versions … 2 files skipped", the four outcome lines and the two grouped skip lists; with index on and no ready embedding model the job reported "The run failed: NoModelReady: embed …" honestly.
**Review (code-reviewer, 2026-09-21).** Blocker fixed: Ctrl-C in the CLI is now a clean stop through a SIGINT handler (`should_stop`), never a task cancel that could land inside an aiosqlite commit; a second Ctrl-C aborts. Majors fixed: missing decoders, oversize files and lockfiles classified as `retryable_error`/`gated`/`gated` instead of `parser_error`/`unsupported`; a resume retries `retryable_error` items and keeps the interrupted run's own settings (trust tier, media, language — form/CLI values are ignored, tested); the app's shutdown asks a running job to stop and waits, so it is recorded `interrupted`; the task runner moved to `knowledge/ingest/jobs.py` (thin router, logging, own repo closed, finished jobs pruned to the last five); deterministic stop→resume test over HTTP plus a real `task.cancel()` test; the per-file line is no longer announced on every poll (`aria-live=off`; outcome counts in a separate polite region); the private prompt pack is git-ignored. Minors fixed: an archive's own outcome reflects its members, `files_done` counts at record time, a run is marked `resumed` as soon as its continuation starts, `course IS NULL` on the CLI resume lookup, running outcome counters, stop feedback in the UI, ARCHITECTURE §4 row. Recorded: OLE-magic sniffing for legacy/encrypted Office files (still `parser_error` with the hint).
**Not covered / limits.** A resume skips by URI: a file or archive that *changed* between the interruption and the resume is picked up by the next plain run (hash idempotency), not by the resume. Progress inside one huge file (a 3-hour video being transcribed) is still a single step — the current uri says which one. A run that dies without Python running its handlers (kill -9, power loss) stays `running` in the table; `--runs` shows it and it cannot be resumed until marked (owner: rerun without `--resume`, idempotency makes that safe). One background job per process. The live `data/dev.db` was not touched by any of this.
