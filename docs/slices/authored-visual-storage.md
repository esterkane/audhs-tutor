# Authored visual storage foundation — G4

Preserve private, learner-owned visual documents and immutable numbered versions
outside the disposable representation cache. Separate raw generation snapshots so
learner backups retain derived content/reviews but omit raw snapshot material.
Inputs/outputs in this slice: schema migration and recovery/export/wipe boundaries.
No API, model calls, events, grading or learner interaction; mode/energy unchanged.
No new UI accessibility surface. Accepted lifecycle: design/AUTHORED-VISUAL-LIFECYCLE.md.

Tables: document (mutable title/archive/revision), version (exact spec and binding
hashes, original author/model/prompt metadata), raw source snapshot, exact-version
review, and idempotent operation receipt. Composite ownership foreign keys prevent
cross-learner relationships. Immutable records reject UPDATE; deletion remains
available to explicit learner wipe. No individual purge endpoint is introduced.

Follow with transactional save/review/archive
repository, bounded typed answer visual envelope, concurrency/retry validation,
and revalidation in the acceptance transaction before exposing any write endpoint.
This schema alone does not approve content or provide functioning visual authoring.

## Existing architectural issue found
The all-table fixture exposes pre-existing learner-wipe FK failures when a shared
Representation references a learner-owned model_call, and when unscoped experiment
arms reference a learner experiment. Authored visual records have no such shared
reference. The dedicated wipe fixture includes both learners, shared corpus and all
five visual tables (without unrelated experiment/cache rows), then checks removal,
retention of the other learner and shared corpus, and foreign-key integrity. A separate
cache/experiment-arm wipe regression is queued; do not claim all historical wipe paths
are fixed by this schema. No production workaround was silently added here.
