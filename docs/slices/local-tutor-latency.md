## Bounded improvement
Ollama complete/stream calls now send a configurable `keep_alive` duration. `OLLAMA_KEEP_ALIVE_S` defaults to 1800 seconds (30 minutes), accepts 0–86400, and is wired through Settings/provider factory. Use 300 to restore the prior five-minute idle policy or 0 to unload after calls. No new dependency, model switch, hosted call, prompt truncation, automatic generation or learning-policy change.

The current model occupied approximately 8.3 GB while resident. Memory pressure/model competition can still cause eviction; this is not a permanent memory reservation or a latency guarantee. Embedding and benchmark-only native calls retain their existing behavior.

Official contract: [Ollama model residency](https://docs.ollama.com/faq#how-do-i-keep-a-model-loaded-in-memory-or-make-it-unload-immediately). Installed LiteLLM chat transformation forwards keep_alive at the top level of the native request.
