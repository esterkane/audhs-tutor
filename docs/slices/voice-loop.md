# Slice: voice-loop (P9, 2026-09-20)

**Story.** With voice activated, the session screen gets "Talk instead": the learner presses Talk, speaks, sees the transcript, gets the ordinary tutor answer streamed as text and spoken aloud, can interrupt at any moment, and can type in the same conversation. The tutor turn is unchanged (bounded ContextPacket, citations, policy, `asked`/`explained` events); voice only adds ears and a mouth.
**Protocol (`WS /api/voice/ws`, `app/voice/loop.py`).** client: `start{session_id, skill_id?, lang?, text_only?, conversation?}`, binary PCM16 mono 16 kHz frames, `end_of_speech`, `text{text}`, `interrupt`, `stop`; server: `ready{stt, tts, vad, text_only, why_text_only}`, `listening`, `transcript{text, language}`, `nothing_heard`, `meta`, `token{text}`, `audio{pcm16_b64, sample_rate}` (24 kHz from Kokoro), `interrupted`, `done{turn, latency{stt_ms, llm_first_token_ms, tts_first_audio_ms, total_ms, interrupted}}`, `error{message, fallback?}`. Server VAD (`app/voice/vad.py`: adaptive energy detector, Silero ONNX when installed) ends an utterance after 700 ms of quiet or 60 s; < 300 ms of speech → `nothing_heard` (empty/noisy input never becomes a turn). Sentences are synthesized as they complete (`sentences()` splitter) so the first audio does not wait for the whole answer. **Interruption is cooperative**: `interrupt`, a new utterance (barge-in detected as *speech*, never as trailing silence) or typed text set a flag; the turn stops consuming tokens, closes the tutor generator so its own finally runs (trace, `explained` with partial route, checkpoint), the speaker stops between chunks, then `done{interrupted: true}`. Tasks are never cancelled outright — a cancel inside an aiosqlite call wedges the shared connection (found during the slice). One DB session per socket, used by one coroutine at a time (TTS `model_call` rows are written after the turn).
**Fallbacks.** `text_only` when requested or when STT/TTS is not ready (`why_text_only`), typed `text` always works, STT failure → `error{fallback: "text"}` + `model_call(ok=False)`, TTS failure → the answer stays readable, `nothing_heard` → "try again or type". Client disconnect → the loop stops; a fresh socket on the same session resumes (nothing was stored on the socket).
**Events + logging.** `spoke` per turn (`stt_ms, llm_first_token_ms, tts_first_audio_ms, total_ms`; context `stt_model, tts_model, lang`), `model_call` rows for every STT and TTS call (free, `usage_source` unavailable/reported), the tutor's own `asked`/`explained`/traces. **Retention:** recordings are held in memory for the transcription only; with `voice.retain_audio` on they are written to `VOICE_DIR/<session>/<utc>.wav` and pruned beyond `voice.retention_days` on every write (`prune`). Test recordings are never kept.
**UI.** `features/voice/useVoiceLoop.ts` (WebSocket + `startMic` ScriptProcessor → 16 kHz PCM16 frames + `Player` queue with immediate stop; nothing connects or records without a click), `VoicePanel` (Connect → Talk/Done → transcript, streamed answer, Interrupt, Stop voice, "Type instead" always visible, latency line, status via `role=status`, errors via `role=alert`), wired into the session screen's tutor panel when `voice.enabled`.

**Benchmark evidence (2026-09-21).** `scripts/bench_voice.py` gained `--transcripts` (word error rate against reference text, Levenshtein over normalised words), `--dataset` and `--own-recordings`; it now measures each stage on its own (STT, LLM first token, LLM generation, first sentence ready, pure TTS synthesis, total to first audio with TTS started at the sentence boundary exactly as this loop does) and projects a first-clause start from the clause's separately measured synthesis time. The report carries `dataset`, `own_recordings`, `stage5_gate`, `wer_*`, `stages_median_ms` and `latency_target_met` separately from `passed` (which needs both the latency target *and* own recordings). First real run on LibriSpeech dev-clean: WER median 0 / mean 3.2 %, first audio median 2.30 s (target 2 s), first-clause projection 1.76 s — see ROADMAP Stage 5. The registry is seeded on a disposable DB so the benchmark never touches `data/dev.db`.

**First-clause speech (2026-09-21).** `speech_chunks(pending, first, early)` decides what the speaker gets: whole sentences always; for the very first utterance of a turn with `voice.early_speech` on (default, reversible in Preferences) the first closed clause (`first_clause`: comma/semicolon/colon after ≥ 3 words with text following) goes out at once and the rest of that sentence follows as its own chunk — a small prosodic seam bought 0.3–0.5 s of first audio (bench: 1.97 s vs 2.30–2.45 s median on LibriSpeech, run-to-run drift ±0.15 s). Later chunks never split at clauses; short interjections (Yes, …) are skipped for the next delimiter; delimiters inside code spans, open brackets or citation-only heads do not count. The `spoke` event's context carries `first_chunk` (`clause`/`sentence`). Tested token by token in `test_first_clause_and_speech_chunks` and through the WebSocket loop with the fake tutor (clause first, then sentences; preference off → whole sentence).
**Found by the new WS test (pre-existing, fixed 2026-09-21):** after a sentence split the loop kept `sentences()`'s *stripped* remainder, so a provider that streams tokens with trailing whitespace (the fake does; Ollama usually leads with the space) glued the next word onto the previous one ("Thenone more sentence"). `speech_chunks` now cuts at the last sentence boundary and keeps the remainder verbatim.
