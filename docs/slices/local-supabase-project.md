# Local Supabase project and reviewed diagnostics

The host imports a pinned source snapshot of the owner-selected Supabase/PostgreSQL tutor. It uses the existing local model registry and attempt ledger for generated study answers and embeddings; ordinary project study has no hosted route or budget. The main author's optional hosted workflow remains separate. Missing project configuration or unavailable PostgreSQL does not prevent the rest of the app from starting.

Reported table/schema permission errors, missing relations/columns and rejected row-security writes now select reviewed diagnostic plans. A bare insufficient-privilege code gets a separate explanation of its ambiguity rather than a guessed table-grant diagnosis. SQL is fixed, read-only catalog inspection, without interpolated learner identifiers, automatic execution, invented results or automatic fixes. Role/identity and information-schema visibility limits are explicit. Actual application-role and JWT checks remain distinct from an administrator inspection. Learner-owned incident fields and append-only transcripts are preserved; these plans do not establish root causes, award mastery, or replace learner hypotheses. A role already reported is not requested again.

The earlier narrowly reviewed conceptual comparison remains available. Other cases still delegate to the local tutor; this release does not certify arbitrary generated SQL or every possible incident. Mixed error reports, active lab contexts, exams and unknown issues retain their existing analysis flow.

The imported workspace is reachable from the Supabase project brief. Optional personas and session language remain explicit. Host presentation removes a nested main landmark, improves muted-text contrast and makes horizontally scrolling code keyboard-accessible.

Verification uses isolated learner identities: focused backend/bridge/state invariants; real local PostgreSQL read-only execution of all diagnostic plans; API cases for the five error families; and a configured Chromium journey covering incident replies, a protected learner hypothesis across a second turn and reload, saved project writing, authoring handoff, mobile overflow and axe. Normal CI covers unconfigured readiness, project evidence persistence and the existing full uploaded-material authoring/activation/study/resume journey. `supabase-configured-audit.spec.ts` is opt-in via `AUDHS_SUPABASE_CONFIGURED_AUDIT=1` against a deliberately isolated configured stack; its normal sandbox run is skipped. No databases, credentials, machine configuration or captured learner data are part of the release.

Release gates: 2,529 backend tests passed (one skipped), with the latest 52 affected integration checks passing separately; 807 frontend tests passed. Strict mypy passed for 327 application files, Ruff and TypeScript/ESLint/build passed, two project/readiness browser journeys passed, the full focused upload-to-study/resume journey passed, and the actual configured-host Chromium incident/project/authoring-handoff journey passed with mobile axe checks. Five error classes were reproduced inside a rolled-back PostgreSQL fixture, and every fixed diagnostic query executed read-only. The five initial real host replies took 21–23 ms and restored their transcripts. These timings measure reviewed reply reuse, not general model decoding.
