# Slice: guided-listening (P7, 2026-09-20)

**Story.** In the language block the learner can listen to one bounded clip of a recording they already ingested (course lecture, podcast, own recording with its caption/transcript), answer one comprehension question, see feedback after rating their confidence, and choose "next clip" or "stop here". Playing is exposure and is logged as such; only the answer produces evidence and a scheduled card. Text-only when there is no audio file.
**No parallel lesson database.** A lesson = an ingested document with timed chunks (`udemy_caption`, `transcript`, `audio`, `video`); the clip list = the document's chunks bounded by `bound_sections` (`kernel/listening.py`): missing/negative/zero-length cues skipped, overlaps clipped to the previous clip's end, cues longer than 240 s or shorter than 2 s skipped, cues beyond the audio's end skipped (duration read from WAV headers; other formats: unknown → no check), every skip carries a reason. Audio = the document itself or a media file with the same language-stripped stem next to it, served only when it is a plain file under `INGEST_ROOTS` (`open_target`, 2 GiB cap, Range-capable `FileResponse`). Language from the caption suffix (`.en.vtt`). Progress = attempts on the clip's task (derived, not stored twice).
**Tasks.** One `assessment` row per clip on the per-language node `lang-<xx>-listening` (`domain=language`, `teachable=false`, kind `listening` — never a tutor lesson). `item_json.listening = {document_id, chunk_id, t_start, t_end, origin, model_call_id, validated}`. Origin `model`: `orchestrator/listening.py` asks the routed local model (`TaskClass.GEN_ITEMS`, prompt `prompts/listening/comprehension.v1.md`, transcript inside a tagged data block) for one four-option question, then checks deterministically (four distinct non-empty options, correct option shares a word with the transcript); a failed check or no ready route → `deterministic`: a cloze cut from the clip's own sentence (content word ≥ 6 letters). Model items are labelled `validated=false` in the API and UI ("proposed by the local model … report it if it is wrong"); the P4 report action covers them. Answers go through `POST /api/assess/attempt` unchanged → attempt row, `attempted`/`graded`/`evidenced`/`reviewed` events, competency evidence on the listening node, one FSRS card per clip. The grader now stamps events with the **skill node's domain**, so listening tasks produce language-domain events (previously every attempt was `ai_ml`).
**Events.** New verb `listened` (`result {replays, seconds}`, `context {document_id, clip_index}`, object `<document_id>:<clip_index>`) — exposure only, never evidence; the rest are the existing assessment events with `domain=language`.
**API.** `GET /api/listening/lessons`, `GET /api/listening/lessons/{document_id}` (sections, skipped with reasons, `media_url` or a `media_note`, `next_index`), `GET …/media`, `POST …/sections/{i}/task` (`session_id`, `use_model`), `POST …/sections/{i}/listened` (204). Preference `listening.document_id` picks the lesson offered in the block.
**UI.** Language screen › **Guided listening** card picks the lesson (audio availability shown). Session language block → `LanguageBlock`: two concrete options when both exist (vocabulary due / guided listening at clip k of n), otherwise the one that exists. `ListeningPanel`: `<audio preload="none">`, **Play only on click**, stops at the clip end (`timeupdate`), Replay from start, Show/Hide transcript, playback error → reading version; task after "I have listened — go to the question" (logs `listened`); confidence before feedback; "Try once more" on a wrong answer; then **Next clip / Stop here** — stop is the primary action on low capacity ("enough for today") and after the last clip. No autoplay, no motion, keyboard-native buttons, `role=group` on playback controls, `role=status` for feedback.
**Mode/energy.** The block itself is planned by the existing planner (`planner.language`, energy ≥ 3). Low capacity: stop is primary after each clip (next clip stays available as secondary) and the model is not asked (source-cut cloze at once). **Sensory:** no sound plays without a click (independent of `ui.sound`, which gates app sounds).
**Donor.** `lernapp-updates @ 8b27582` `services/media_lessons.py`: principles reused — bounded section semantics (~240 s), clip bounds validated against the audio, saved answers, "always show the supplied text, never a model substitute", grounded-question checks; not copied: PyAV clip re-encoding (not an approved dependency — bounds are enforced client-side on the `<audio>` element and the served file is the original), German UI, exam tables, frontend. **Limits.** Clip bounds are enforced by the browser element, so a learner *can* scrub beyond a clip with native controls (they are hidden; the buttons drive the element). Media duration is known for WAV only; MP3/M4A lessons cannot detect a too-short recording (cues past the end simply fail to play → text-only). Model questions are unreviewed proposals until the learner reports or the corpus review path (P4 drafts) grows a "listening items" review. Only ingested material: no upload endpoint (roots + ingest limits apply).
