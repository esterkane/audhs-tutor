# Slice: code-editor (ADR-0013 follow-up 2, 2026-09-21)

**Story.** The code exercise gets a real editor: Python-aware indentation, undo history, line numbers, soft wrapping — without giving up the accessibility guarantees of the textarea it replaces. The learner can switch to the plain editor at any time (remembered per browser), and the plain editor is also what appears when CodeMirror cannot start.
**In/out.** `features/code/CodeEditor.tsx`: `CodeEditor({ id, value, onChange, plain, onPlainFallback })` renders CodeMirror 6 (`@codemirror/state`, `view`, `commands`, `lang-python` — the four declared packages; `@codemirror/language` is *not* declared, so there is no syntax colouring yet, only parser-driven indentation) or the plain `<textarea>` with the previous Tab/Shift+Tab/Esc handling. Keymap: `Escape` → `simplifySelection` + `setTabFocusMode(true)` (**sticky**: the next Tab or Shift+Tab moves focus out, however long it takes and whatever navigation keys come in between — CodeMirror's stock `temporarilySetTabFocusMode` only holds for two seconds, which is a timing trap for a keyboard-only learner), a `focus` handler switches tab-focus mode off again when the editor is re-entered, then `indentWithTab`, `defaultKeymap`, `historyKeymap`. The content element carries `aria-labelledby` to the visible label, `aria-multiline`, spellcheck/autocorrect off. Theme from the app's CSS tokens (`--color-card/fg/line/accent/muted`), 3 px focus outline, `color-mix` selection. Value ownership stays with `CodeExercise`: a Reset or restored draft flows in through `value` (synced by dispatching a whole-document replace when the doc differs), edits flow out through `updateListener`. `features/code/editorPreference.ts`: `code-editor:plain` in localStorage. `CodeExercise.tsx`: label text differs per editor ("Tab indents — Esc then Tab leaves" vs. "Tab inserts two spaces — Shift+Tab, or Esc then Tab, leaves"), a "Switch to the plain/code editor" button, a `role=status` note when CodeMirror failed to mount and the plain editor took over.
**Events.** None; the editor is pure UI (the draft stays a per-viewer convenience in localStorage, as before).
**Mode/energy.** Unchanged. No motion, no autoplay.
**Accessibility.** Both editors are labelled textboxes (`htmlFor` only for the textarea; the CodeMirror content element is named via `aria-labelledby`); Tab never traps (Esc then Tab without a time limit, or Shift+Tab in the plain editor); the switch is a plain button; focus ring from `--color-accent` (3 px; contrast not measured here); `reducedMotion` irrelevant (CodeMirror animates nothing).
**Verified by.** `CodeExercise.test.tsx`: new test — CodeMirror mounts by default with the accessible name, the switch keeps the code and is remembered, an external Reset flows into the mounted editor, axe clean; `CodeEditor.fallback.test.tsx`: a mocked `EditorView` constructor throw lands on the plain editor with a `role=status` note and does **not** persist the plain preference, and trying again fails the same way; the three interaction tests now run on the plain editor (jsdom cannot type into CodeMirror; `src/test/setup.ts` polyfills `Range.getClientRects` so CodeMirror mounts there). Browser: `e2e/code-editor.spec.ts` (Playwright, real Chromium): typing with auto-indent, Tab increases the line's indent, Escape then (after a 2.5 s pause and an arrow key) Tab focuses the next control, re-entering restores Tab = indent, the draft is restored and announced after a reload, the plain editor shows the same code, Reset returns the starter code. Locally on 2026-09-21: `make lint` green; vitest 41; `make test-e2e` 4 passed.
