# Slice: usage-accounting + budget-reservations + cost-view (P6, 2026-09-20)

**Story.** The learner can see what hosted models cost today, how sure each figure is, which calls failed or needed retries, and why a task has no model — and the daily cap can no longer be overshot by concurrent calls or fooled by a failed call that "cost nothing".
**Accounting (`model_call`, migration `ac95f48189c0`).** One gateway call = one `request_id`; every provider attempt is its own row: fallback model, structured-output repair, blocked-by-budget (`attempt` 1..n, unique `idempotency_key` = `request:registry:attempt`, `outcome ok|error|invalid_output|cancelled|partial|blocked`). `usage_source` = `reported` (provider usage, incl. the final usage chunk of a stream via `stream_options.include_usage`) | `estimated` (chars/4 when a stream sends no usage; Anthropic and Ollama both request it) | `unavailable` | `legacy` (every pre-P6 row; tokens there may be estimates — labelled, never re-derived). `cost_status` = `free` (local) | `reported` (LiteLLM `completion_cost` taken as is — prompt caching legitimately makes it lower than the registry estimate, which is kept in `metadata_json.registry_estimate_usd`) | `estimated` (tokens × registry price) | `unknown` (failed hosted call with no usage; `reserved_usd` is what the cap counts — **a failed call is never confirmed free**) | `legacy`. Duplicate writes with the same idempotency key return the existing row (`write_model_call`). Cancelled streams (learner stop **or** client disconnect → `asyncio.CancelledError`) and mid-stream breaks keep their rows (`cancelled`, `partial`) with estimated tokens; a `partial` turn still reaches the learner as a `done` with `outcome=partial` (the text they read stays; the session screen says "Answer cut short"), never as a raw exception.
**Repairs.** Providers make one Instructor attempt (`max_retries=1`, exceptions carry the attempt's usage and invalid text); the gateway logs it, appends the invalid reply + a repair instruction and retries up to `MAX_REPAIRS=2` times, then emits `invalid_output(attempts=3)` and escalates one tier. **Changed semantics:** before, Instructor made two attempts per model and the second failure escalated; now three invalid replies (1 + 2 repairs) escalate, each visible as a row, and the repair turn carries only the validator messages (`input_value=` fragments of the model's reply are omitted — model output never gets user authority).
**Reservations (`budget_reservation`).** Before a hosted attempt: `worst_case_usd` = (prompt chars/4 + 16/message) × price_in + `max_tokens` × price_out — the output is bounded by `max_tokens`. `Budget.reserve` runs under one per-process lock (`app.state.budget_lock`): expire stale reservations (> 10 min, `expired`), compute counted spend = reported + estimated + legacy hosted cost + unknown-at-reserved + open reservations, refuse when counted + bound ≥ cap (`blocked` row, `degraded` event, local fallback), else insert `open`. After the attempt: `reconcile` (settled = cost, or the reserved amount for `unknown`), `release` when the provider was never reached. **Policy for unknown cost:** counted at the reserved worst case until the day rolls over. **Limitation:** the lock is per process; a second backend process could overshoot by one reservation (Phase 1 runs one). Provider billing is still LiteLLM's view: Anthropic cache-read/write pricing is not itemised, and streams without a usage chunk are estimates — both stated on the row.
**Surfaces.** `GET /api/models/costs?days=` → cap, today {counted, remaining, reported, estimated, unknown_reserved, legacy, open_reservations}, window counters (hosted/local/failed/blocked/retried/unknown/legacy/expired), by task, by provider, recent failures (request id, attempt, outcome, billing). Models screen › **Hosted spend** card (no blended number; failures collapsed). `GET /api/models/routing` rows gain `problem` + `action` when nothing is ready ("hosted-strong is hosted and ANTHROPIC_API_KEY is empty — set ANTHROPIC_API_KEY in .env and restart the backend"; "gemma3-12b is not downloaded — pull it under Models"). Session screen: a one-line notice **only when the route was not the planned one** ("Answered by a local model instead of the planned hosted one: today's hosted budget is used up. Nothing else changed." / fallback) and "Answer cut short" for partial turns; the registry id and "token usage estimated" sit in a collapsed "About this answer"; `tutor_failed` errors are a fixed learner sentence (detail in the log), never `str(exc)`; `explained` events carry `usage_source`/`cost_status`; `TurnDone` too.
