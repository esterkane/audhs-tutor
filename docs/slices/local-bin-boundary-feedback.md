The workspace now inspects direct top-level pd.cut/pandas.cut calls with bounded literal numeric edges and literal supported options. It derives boundary-to-bin membership without executing code or importing pandas. For answer-check requests containing a supported literal call, the response is a dedicated deterministic boundary result, with supplied labels and no model verdict or call. It explicitly states that the written answer and other claims are not graded; it does not infer compliance with natural-language exercise requirements. Ordinary explanation/chat requests retain model assistance and a separate conditional-facts prefix. Hint requests do not reveal the boundary solution. Results are saved with checker version and exact request context.

Assumptions and limits: the named binding must refer to unmodified pandas.cut and valid input must be supplied. This is not dataset validation, alias resolution, evidence of execution, or a grade. Dynamic bins/options, nested calls, scalar bin counts, IntervalIndex and unsupported arguments abstain. At most three calls and sixteen edges per call are inspected within bounded input/AST limits. Labels are never copied into trusted prompt text. Zero-based stored bin indexes are displayed as one-based bin numbers. Changing workspace prompt version to v13 excludes earlier exact-answer reuse.

Semantics were checked against [official pandas.cut documentation](https://pandas.pydata.org/docs/reference/api/pandas.cut.html): right=True uses right-inclusive intervals; include_lowest includes the initial edge; right=False uses left-inclusive intervals. No dependency is added.
