# Slice: curriculum-drafts (P4, 2026-09-20)

**Story.** Ingesting a course makes it *searchable*; it becomes *learnable* only through a reviewed curriculum. The learner picks a course section, gets a draft (skills with prerequisites, one learning object per skill with linked source passages, source-cut cloze candidates), edits it, sees every validation problem, and publishes explicitly — or rejects it. Published lessons are versioned so later edits never rewrite what earlier evidence pointed at (review finding 7).
**Statuses.** Material: `imported` (documents) → `searchable` (indexed chunks) → `draft` (an open draft exists) → `published` (skill nodes carry the course). Draft: `draft` → `published` | `rejected`.
**In/out.** `kernel/curriculum.py`: `material_status`, `sections_of`, `section_material` (latest-version unique chunks per lecture), `propose_payload` (deterministic: one skill per lecture in **file-number order** (`path_numbers` re-derives `NNN` from the path; labels are stored number-stripped), slugs scoped `course-section-lecture` and unique within the draft (`lecture_slugs`), description = a literal "Lecture 'X' in course › section (N passages)", `sources` = chunk ids, cloze candidates = a source sentence about the lecture with a **content word** blanked — `auto: true`, never invented; when only a title word qualifies the item is `guessable: true`; success criteria / examples / exercises are left **empty on purpose** so the validator's warnings show what the learner has to write), `validate_payload` (shape, duplicate slugs, unknown prerequisites, cycles over the draft **∪ the published graph**, orphan learning objects/assessments, missing learning object / concept / goal, ≥ 1 assessment per skill, malformed items, source chunks that no longer exist; warnings: no success criteria, no exercises, guessable cloze, model item without a linked passage, 'explanation' required without an `explain_back` item), `create_draft` / `update_draft` (version +1, re-validated) / `reject_draft` / `publish_draft` (nodes upserted with `skill_node.course`, edges added, a **new `learning_object` version** when content changed, assessments added when new — `item_json.draft_id` records provenance; errors block). `orchestrator/drafting.py`: optional model path (`TaskClass.GEN_ITEMS`, quoted excerpts in a tagged block, `DraftSuggestions` schema) merges goals/criteria/exercises/one MCQ per lecture into the deterministic draft; every touched skill/object carries `origin: "model"`, the MCQ carries `source_chunk_id: null` (the model saw several excerpts — no single passage is claimed) and the draft the `model_call_id`; prompt `prompts/curriculum/draft.v1.md` (`prompt_version` in `model_call.metadata`); only `NoModelReady | GatewayError | ProviderError | BudgetExceeded` fall back to the deterministic draft, which is then labelled `origin="deterministic"` with a visible "model route unavailable" note (never "model" for a draft no model touched). Tables `curriculum_draft`, `content_report`, column `skill_node.course` (migration `367349aa228b`; the seed loader stamps its `course`). API `/api/curriculum/{material,sections,drafts,drafts/{id},drafts/{id}/publish,drafts/{id}/reject}`; `PUT drafts/{id}` takes a typed `DraftPayload` (shape + size caps → 422, the kernel adds the semantic problems). UI `/curriculum`: courses with status → sections → "Propose a draft" (model checkbox) → draft list → editor (per-skill summary, JSON, save and re-validate, problems listed, publish disabled while errors exist, reject); sections and drafts collapse once a draft is selected (one open task). Drafts are per learner (`material_status(db, learner_id)`).
**Events.** None (content management). Model drafting writes a `model_call`; published assessments feed the existing `attempted`/`graded`/`evidenced` flow.
**Mode/energy.** Not session-facing.
**Accessibility.** Native buttons/lists with labels, `role=alert` for problems and failures, `role=status` for results; the JSON editor is a labelled textarea (a form editor is a follow-up).
**Verified by.** `tests/test_curriculum.py`: status transitions on a real ingested sample course, deterministic draft shape (prerequisite chain, sources, cloze from source), **lecture order from file numbers** (Inputs: Tokenisation → Positional; sections Inputs → Attention), section-scoped unique slugs, validation catches cycles (incl. one closed through already-published edges), orphans, unknown prerequisites, missing pieces, broken sources and blocks publish, publish creates nodes + v1 objects + assessments, re-publish writes v2 and keeps v1, published drafts immutable, reject, `use_model` without a ready route → deterministic + note, `use_model` with a ready fake route → proposals merged and labelled, invented lectures dropped, MCQ without fabricated provenance, invalid model output → deterministic; malformed `PUT` → 422. `Curriculum.test.tsx` (propose → problems → blocked publish → edit → publish).
**Review (code-reviewer + pedagogy-reviewer, 2026-09-20).** Fixed: lecture order was alphabetical (blocker), slug collisions across sections, orphan LO/assessment → `KeyError` 404 on publish, cycles through published edges, `origin="model"` on fallback drafts, fabricated `source_chunk_id` + `auto` on model MCQs, broad `except Exception`, inline unversioned prompt, title inside an XML attribute, drafts counted across learners, untyped hand-edited JSON → 500, title-word cloze that is guessable from the header, boilerplate success criterion that silenced the validator, transcript openers passed to the tutor as "examples", `/curriculum` stacking four open cards. **Recorded, not done:** `UniqueConstraint(skill_id, version)` on `learning_object` (concurrent double-publish; needs a batch migration), seed-loader dedupe ignoring published items with identical content, a form editor instead of JSON, cap on reports per turn/chunk, a `published` event so traces can explain jumps in item counts, `_body` still imported privately by `drafting`.
**Open.** The editor is JSON; `explain_back` rubrics must be written by hand; the model path is untested against a live model (no `gemma3:12b`); no "unpublish" (publish a corrected draft instead).

**Source selection (stage 3, 2026-09-21).** Drafts are built from a section's *primary* documents only; supplemental and excluded documents (owner decision or literal suggestion) are listed in the draft's `info` notes — `docs/slices/course-curation.md`.
**2026-09-21 (course-curation).** Drafts carry `payload.selection` (what they were built on; see `docs/slices/course-curation.md`); `update_draft` and `publish_draft` re-derive the `info` notes from it, so a hand edit never loses them unless the selection itself is deleted from the JSON.
**2026-09-21 (first live drafting, LLM Engineering course).** Three defects found by drafting a real course with the local model, all fixed with tests: (1) one call per section overran the local models' output limit ("output is incomplete due to a max_tokens length limit" on gemma3:12b and llama3.1:8b for 8 lectures) → `drafting.draft_with_model` asks for `LECTURES_PER_CALL = 3` lectures per call with `MAX_TOKENS_PER_CALL = 2000`, merges the replies, logs each call with `metadata.lectures = "1-3/8"`, and returns the titles of lectures whose call failed so the route adds a warning naming them (those lessons stay deterministic); (2) the excerpts quoted the first four passages of each notebook, i.e. `pip install` and import cells, so the model proposed lessons about installing packages → `teaching_chunks` picks the passages with the most prose outside fenced code (setup lines never count), in source order, falling back to the first passages only when none has prose; (3) every document of a lecture became its own skill (an archive's Dockerfile/main.py/main_FastAPI.py = three skills titled "Serving transformers with FastAPI") → `section_material` builds **one slot per lecture label**: documents filed under the same lecture are one lesson with all their passages (grouped per document, then by ordinal), `documents` lists them, the skill description says "N documents", and `selection.built_on` still counts documents (each with its `lecture`).
**2026-09-23 (first rehearsal of the learning loop on a published course).** `scripts/rehearse_course.py --course NAME [--sessions N]` publishes a course's open drafts on a private online-backup snapshot (`data/rehearsal.db`; hosted providers off, budget 0), sets `goal.course`, and runs N sessions the way the learner would meet them: explain + hint turn with citations checked against the course, the assessment rotation graded through the real grader, competency refresh, FSRS due queue, session end; report in `evals/results/rehearse_<course>.json`. Two defects found, both fixed with tests: (1) **the first skill offered depended on publish order** — `topological_order` breaks ties by insertion, so the last-drafted section supplied the first lesson → `skill_node.section` + `skill_node.order_no` (migration `d4a7b2c9e1f0`; section order as `sections_of` lists it × 1000 + lecture position, stamped at publish) and the goal-narrowed pick in `next_skill` sorts by it (`_pick` still never returns a locked node; without a goal the map order is unchanged; order is *not* a prerequisite); (2) **mastery could never pass 0.42** — skills require the `explanation` dimension but drafts carried only clozes and model MCQs, so the same lesson stayed current forever (the validator's warning was easy to publish over) → `explain_back_item` per skill in the deterministic draft (prompt "Explain '<title>' in your own words …", rubric of three literal criteria keyed on the lecture's `salient_terms`, or the skill's success criteria when the model supplied them via `rubric_from_criteria`), so the rotation mcq → cloze → explain-back is complete and the rubric/LLM grader gets exercised.
**2026-09-23, second and third rehearsal (same course, regenerated drafts).** Progression now works (mastery 0.42 → 0.51 → 0.61, then the next skill) once the explain-back answer carries lecture content — a generic answer scores 0 with the local grader, correctly. Two more defects, fixed with tests: (3) **the course's sections sorted alphabetically** ("chapter 2 …" before "Model …", the unsectioned root notebooks first) because `path_numbers` only understood the plain `NN - Section/MMM - Lecture.ext` layout, not the resources export `Section N - title/Lecture a-b - M. title/asset` → it now reads both layouts from the *outer* path (an archive member's own path rarely carries the numbering; a numbered archive file is its members' lecture slot) via the ingest's `parse_section_dir`/`parse_lecture_dir`, and `sections_of` sorts the unsectioned root files last; (4) **the tutor cited another course's notebooks in a course lesson**: `tools.retrieve` widened from the skill filter straight to the whole corpus → it now widens skill → the skill's course → corpus, records `filters.widened` (`["course"]` / `["course","corpus"]`) in the retrieval trace, and `TutorTurn` passes `node.course` (`tests/test_retrieve_scope.py`). Turn latency in the rehearsal: median 15–17 s per explain/hint turn with `gemma3-12b` on the `explain` route (streaming hides most of it; assigning `explain` to `llama31-8b` in Settings › Models is the owner's call, not changed here). (5) The instructor's repository (downloaded as external material) contributes the "chapter 2 Transformers Architecture" section without any folder number, so it sorted last while the Udemy export's own "Transformers Architecture" section holds only duplicates of it → `sections_of` falls back to a literal number in the label (`label_number`: leading "chapter/Abschnitt/Section/Module … N"); anything else stays unnumbered and sorts last, after the numbered sections and before nothing — the unsectioned root files sort last of all.
