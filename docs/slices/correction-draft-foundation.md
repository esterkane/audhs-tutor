# Durable correction draft foundation

Internal storage slice of proposed ADR-0019; no public editing API, editor or publication yet. Two learner-owned tables store original question/rubric snapshots, stable server-private fingerprints, original eligibility revisions, candidate scratch content, rationale and immutable logical command receipts. Candidate scratch JSON is size-bounded but explicitly NOT validated teaching or grading content. It has no selector or grader consumer.

Create copies current content under a write lock and optionally verifies the report belongs to the same learner/question and still matches. A withdrawn/changed report conflicts rather than rebasing. Save/discard compare draft revision; exact command retries replay their original receipt without changing newer work. Reusing a request ID with different input conflicts. Discard preserves history. Saving edits does not check current source/content freshness because retaining work is safe; future preview/publication must check those identities and must not imply validity from a save.

Caller owns commit/rollback. Learner-row no-op writes acquire SQLite serialization before receipt/revision reads. Private original snapshots and fingerprints are not exposed as public answer digests. Existing assessments, attempts, learning events, eligibility and schedules are unchanged. No model, frontend or mode/energy change. The browser flow remains the previously verified read-only inbox.

Migration773f25ae3e92 adds only the two tables and indexes; reviewed out autogenerated FTS drops/recreation. Generic learner export/wipe discovers both tables and removes receipts before drafts/linked reports. Existing shared assessments survive wipe. Replacement assessment ownership and lineage are still separate work, not implemented by these tables.
