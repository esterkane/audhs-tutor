# audhs-learning-ux

Read the selected R-stage and existing audhd-ux/pedagogy skills. Preserve explicit learner choices; diagnosis does not justify inferred modes or universal learning-style assumptions. Confidence remains optional/collapsed and never blocks feedback, stopping or topic change.

Start with the concrete journey: returning learner, empty area, limited time, interrupted task or service failure. Lead with the current topic/checkpoint and Resume/Start; use one target intent for area/course/lesson. Keep courses as provenance within editable cross-course areas. Never silently fall back to unrelated default lessons when an area is empty.

Keep one primary action per phase with explanation/context before assessment, reachable hints/sources, saved-state feedback, parking and stop. Distinguish Pause, Finish and Change topic using the agreed server lifecycle; do not invent a second client learning kernel. Clear/ask-later are bookmarks, not mastery.

Use existing primitives and installed libraries. Provide titles/h1/current navigation, meaningful focus transitions, keyboard operation, conventional single-choice semantics and readable long-form content. Verify narrow width, text zoom, browser zoom, dark/system themes and reduced motion. Keep accessible list/text/table equivalents for graphs and numerical widgets; deterministic code computes quantities.

Axe and screenshots are evidence, not usability or conformance certification. Record owner comprehension separately: can they identify the current topic, next action, saved work, source and exit without coaching? Do not invent an owner pass. Test failure/empty/loading states alongside the happy path. Avoid gamification, hidden adaptation, autoplay and new infrastructure as substitutes for clarity.
